# 交互与材质架构

## 所有权

每个区域只能有一个几何状态拥有者。原生 QQ 保留消息、输入法、权限、搜索、文件与窗口行为；主题拥有下表中的布局和视觉。新增 QQ 变体应扩充对应模块，避免在多个文件重复写同一状态。

| 模块                                | 负责                                           | 对应样式                           |
| ----------------------------------- | ---------------------------------------------- | ---------------------------------- |
| `styles.js`                         | 唯一样式加载顺序，注入与诊断共用               | 所有 CSS 清单                      |
| `dom.js`                            | 可见节点、缓存页面、受保护窗口／媒体边界       | 无                                 |
| `runtime.js`                        | 一次安装的页面变化分类、合帧、当前布局尺寸观察 | 无                                 |
| `dock.js`                           | 作者原有边缘呼出、焦点与弹窗状态               | `shell.css`                        |
| `composer.js`                       | 测量：真实滚动容器、留白、非标准嵌套、局部按钮、输入反馈；不拥有悬浮状态 | `composer.css`、`shell.css`（标题栏） |
| `cards.js`                          | 卡片类消息的底板／文字／细线识别（按绘制结果，不按模板类名） | `cards.css`                        |
| `surfaces.js`                       | 原生浮层的材质根、内部结构清理、资料变体       | `surfaces.css`、`overlays.css`     |
| `pin-groups.js`                     | 原生置顶状态映射与行内短线，不生成组间分隔线   | `pin-groups.css`                   |
| `color-roles.js`、`color-picker.js` | 兼容原配色和独立自定义色                       | `palette.css`、`color-picker.css`  |
| `index.js`                          | 启动、设置、路由、配色、已有消息视觉功能的接线 | `foundation.css`、`bubbles.css` 等 |

`foundation.css` 是基础表面、文字与滚动条；`lists.css` 是连续列表与身份表示；`auxiliary.css` 只包含确实需要的辅助页面规则。已经删除的旧样式层不应重新加载。

侧栏呼出沿用作者 SnowLora 的 8px 整条左边缘、18px 保持余量、250ms 离开等待；顶部 36px 感应与 600ms 离开等待。边缘节点没有箭头或点击切换。左缘可见短线已按要求移除；原有隐藏提示设置只隐藏顶部标记，不删除 Electron 的感应／no-drag 区域。

## 页面变化路径

原生 DOM／焦点／输入／窗口变化 → `runtime` 分类并合帧 → 活跃页面布局与所需功能 → 丢弃主题自己产生的同步观察记录。

页面结构、消息、侧栏、材质和几何是独立任务；新增一条消息无需重新创建编辑器或扫描整份应用逐个改色。缓存页面的父级 `display`、`hidden`、`aria-hidden`、`class` 变化会触发重新选择。尺寸观察器只绑定当前输入区、编辑区、宿主和消息区域，不观察随滚动变化的虚拟行，切换时断开旧目标。

除了这一份页面观察器，路由标题与原生主题模式各有局部属性观察。没有额外的会话、消息到达、群公告或侧栏观察器，也没有持续轮询。鼠标事件最多合到一个待执行帧，始终保留最后坐标；不能用直接丢弃事件的时间节流处理离开。

CSS 完成有界的 200ms 让位动画。运动期间的纯宽度变化不会触发每帧完整几何工作；`liuli-dock-settled` 同步最终尺寸。编辑器实际增高不受这个优化延迟。

## 输入栏约束

原生编辑器保持原节点、原父子关系与事件。输入栏在其父节点（正文卡）内绝对定位，这条规则是静态 CSS；脚本另外找出同时包含消息视口和输入栏的共同宿主，嵌套不标准时用标记与 `display: contents` 把中间布局壳桥接掉。脚本还负责找到真正滚动的那个节点，把输入栏高度作为它的末端留白；会话刚打开或输入栏变高时，如果视图本来就在最新消息处，就跟到底，已经往上翻的读者不会被挪动。当前消息区域消除 `--inputAreaHeight` 的流布局预留，确保点击编辑器后写回该值也不会形成输入栏上方的空档。

输入栏左侧只有一个主题自有的「+」。表情、截图（以及布局设置里置顶的项）是 QQ 自己的工具项：layout-custom.js 给它们加 `.liuli-pinned`，CSS 把它们从收起的工具栏里移到「+」旁边，图标、点击、截图子菜单都仍是 QQ 自己的；主题不复制原生 SVG 定义，也不实现文件操作。表情图标的悬停/点击只在捕获阶段改为「打开表情面板并切到表情包页」，面板已开时不让 QQ 把它关掉。切换页面必须清理旧工具展开状态。输入反馈只落在输入栏右端一块主题自有的小光效层和发送键的颜色上（打字、删除、附件落入、拖文件悬停各一种），光标旁不画任何东西；文件／图片只给原生新节点一个淡入；中文组词、选区及发送逻辑不被主题接管。

多选转发底栏也由 `composer.css` 管理，只判断当前输入区内原生 `.forward-ops` 的显示状态，不用 `body:has(...[style])`。这样隐藏缓存会话不会关闭当前输入框，局部内联样式变化也不会让整个应用重新匹配这条规则。

## 材质约束

一个面板只有一个材质拥有者。`--ll-material-blur` 贯穿工具、输入、菜单、搜索与资料；透明度、边缘与阴影由 `surfaces.css` 统一。结构包装层不画另一块玻璃。定位壳为零尺寸时不能直接成为材质目标。

输入工具／搜索／资料／右键菜单把模糊画在伪元素上，面板根节点不随意添加变换或滤镜。截图／文件子菜单是重要例外：作者源码明确由零尺寸 `.bar-more-menu` 的 `translateZ(0)` 包装建立固定内层的坐标基准。保留这一原生定位契约，不把所有 `position: fixed` 都当作相对视口；具体出处见 [作者对齐记录](AUTHOR-ALIGNMENT.md)。资料只按注册结构或对应独立路由匹配，不从按钮文字推断。隐藏预创建节点同样赋予材质，零尺寸定位壳不作为实际资料的玻璃根。头像、图标、图片背景、媒体、红包和视频渲染不纳入结构底色清理；弹层复用为受保护内容时撤销主题自己的写入。

文字及虚拟列表行不播放缩放动画，也不设置永久 `will-change`。消息切换最多动画八条可见消息，视频与原生皮肤不参与；系统减少动画与页面隐藏会取消受管动画。

## 验证与诊断

新增原生结构变体时，在匿名 fixture 中补充该结构和实际生命周期，而不是预先添加主题属性。重点检查缓存页面排在前面、节点重新挂载、动画中间边界、子菜单焦点及最终鼠标离开。

诊断快照中的 `rendererScheduler` 只包含队列和计数，`dockState` 只含展开布尔值；不采集消息文本或编辑器内容。截图默认仍由用户选择是否纳入诊断。浏览器 fixture 与性能基准不等于 Windows QQ 实机验收。

## 顶部与宿主边界

聊天标题和操作按钮各自拥有玻璃伪元素，标题栏本身不占面板的一行（聊天列从它下面穿过），空白带不接收指针事件；右上窗口控制展开时操作区只横向让开，不给任何容器加纵向间距。左资料仍只给会话列让位。保留作者对标题菜单层级的约束；当前标题容器层级 200，高于悬浮输入栏 120，低于搜索和窗口控件，不使用根滤镜改变固定子菜单的定位。

主题插件 `load.js` 使用同一 WebContents 注册表处理 BrowserWindow 与 WebContentsView，入口只执行一次，页面重载按代次更新。所有路径仍经过 QQ renderer URL 过滤，查询数据不会误触 screen/share 排除；禁止向外部网页、webview、登录、截图、通话或共享面板注入。


## .12 起的三条约定（2026-11-13）

这三条是从 .5–.11 反复「测试通过、实机失败」里总结出来的，改动相关模块前先读。

**1. 布局状态写在静态 CSS 里，脚本只测量。** 悬浮输入栏、悬浮标题栏的定位规则以原生结构为键（作者记录的正文卡 `*:has(> .chat-input-area)`），不依赖脚本写入的属性。脚本漏一帧、节点瞬时不可见或零尺寸、QQ 重建节点，布局都不会掉回原生。`data-liuli-*` 标记只用来把同一套规则扩展到非标准嵌套，以及告诉 CSS 哪个节点是真正的滚动容器。不要再写「找不到就 `clean()` 把布局撤掉」的逻辑。

**2. 拿不准真实结构的地方，运行时自检并回退到已知可用的布局。** 悬浮标题栏靠把聊天列上移到标题栏下面实现；如果某个 QQ 版本不按父容器给这一列定尺寸，`composer.js` 的 `verifyHeader` 连续两次测到不成立，就在面板上写 `data-liuli-header="flow"`，标题栏退回普通的一行（作者原来的布局）。新增类似机制时照这个模式做，不要假设夹具就是真机。

**3. 验收断言用户看到的东西，不断言样式存在。** `tests/acceptance.cjs` 检查的是：展开前中后消息视口的几何位置、最新一条消息是否被输入框挡住、点击实际落在哪个节点、缝隙处的像素。旧测试曾把「操作区 margin-top 是 36px」当成通过条件，而正是这个 margin 把消息区整体下推。动画同理：`fx.no-added-frame-cost` 实测开／关动画时的慢帧数，输入栏里不允许出现合成层动画（透明度／变换），因为它每一帧都会让底下的毛玻璃重新合成。

## 顶部一排与感应区

资料胶囊、聊天标题、聊天操作区、窗口按钮四块玻璃同高（`--ll-top-h` 36px）、同圆角、同一条起始线（8px 留白）。窗口按钮唤出时，操作区只在标题栏这一条带内横向让开（`margin-right` = 窗口按钮宽度，由 `dock.js` 写入 `--ll-controls-width`），不产生任何纵向位移。

顶部 36px 感应带沿用作者的范围，但加了一条：指针正落在原本就摆在那里的原生控件上（右侧聊天操作按钮、左侧搜索框）时，只有窗口最上沿 8px 才唤出胶囊。否则伸手去点按钮会把胶囊唤出来盖住或顶走它。

## 诊断里的结构探针

`diag.js` 的 `structureProbe` 随诊断导出：聊天面板从输入框到 `.aio` 的嵌套链、真正滚动的节点、导航与会话列交界处的盒子、搜索浮层、当前打开的弹层／资料卡、文件与卡片消息行。只记录标签、类名、几何和绘制属性，不读任何文字或属性值。真机表现和夹具不一致时，先要这份导出，再改代码。


## .13：性能约定（2026-11-13）

这一轮是按测量改的，下面几条是测出来的规律，不是风格偏好。

**消息行上不用 `:has()`。** QQ 的虚拟列表滚动时持续创建、销毁消息行。主题原来有几十条以 `.message-container:has(...)` 或「`.aio` 里任意元素`:has(...)`」为主体的规则，每插入一行都会让大量元素重新匹配：快速滚动时样式计算是裸 QQ 的约 90 倍。现在这些事实由 `rows.js` 在 MutationObserver 回调里同步写成属性（在这一帧渲染之前），CSS 只读属性。新写规则时，主体是消息行或其祖先的 `:has()` 一律不要用；主体是很少出现的元素（`.chat-input-area`、弹层根）可以。

**选择器最右侧不要是裸的 `:is(...)` 或 `[class*=...]`。** 浏览器按最右侧那一段的 id/类名/标签分桶，`body … :is(.a, .b)` 和 `[class*=x]` 会被拿去和窗口里每一个元素比对。`css-optimize.cjs` 在加载时把等特异性的 `:is()` 展开成选择器列表（结果逐元素比对过，完全一致）；`[class*=...]` 只能手工改成具体类名。

**每批新消息里不读几何。** 在消息插入后读 `getBoundingClientRect` 会逼浏览器同步重排整页。原来的会话标识每次都取标题的位置，单这一项就占了滚动时一半的布局时间。需要几何的地方（吸底头像）只读跨视口底边的那一组，二分查找，读取次数与消息数量无关。

**消息记录只在消息列表的组件子树里找。** `qq.js` 第一次查到消息列表组件后记住它，之后的查找从它开始，而不是从整个 QQ 界面的根节点走一遍。

**移动中的列表不做 backdrop blur。** 滚动或新消息滑入期间面板带 `data-liuli-moving`，气泡暂时只保留底色，停下 160ms 后恢复模糊。

**新消息动画只在用户停在最新处时触发。** 整列用 `translate`（不用 `transform`，免得覆盖虚拟列表自己的定位）滑回原位，新气泡用 `opacity` + `scale` 淡入；打开会话、翻历史加载出来的旧消息不做任何动画。

测量工具：`tests/scroll-benchmark.cjs`（快速滚动 3000 条的虚拟列表；`MODE=switch` 测打开会话）。

## 视频壁纸画在画布上（.16）

视频壁纸看到的是 `#liuli-video-canvas`：`video-wallpaper.js` 把每一帧复制到这张不透明画布上（`requestVideoFrameCallback`；帧回调停了而媒体时间还在走时，改用动画帧），`<video>` 在画布下面照常播放。原因是 Windows 会把正在播放的 `<video>` 交给单独的硬件图层，QQ 的半透明窗口里这一层显示不出来：用户两次诊断都是「在播放、铺满窗口、首帧已撤、屏幕上没有」，`opacity: 0.999` 也没用。画布按窗口尺寸 × 设备像素比绘制（上限约 400 万像素），cover 在源上裁切，contain 用窗口底色补边。

只在主窗口和设置页播放。独立聊天窗口是 QQ 预先建好、藏在屏幕外的池化窗口，却报告自己「可见」，在那里播放只会白白解码，所以它和其它小窗口一样只显示首帧。非主窗口里视频层与图片壁纸同层（`#app` 隔离后 `z-index: -2`，在图片后面插入，因此盖住图片、仍在窗口底板和内容下面）。

画不出来（拿不到 2D 上下文或绘制报错）时撤掉画布，`<video>` 本身重新当壁纸，和 .15 一样。

主窗口里视频层插在 `.global-container` 的正前面（同一父元素），并强制 `visibility: visible`（.17）。用户截图显示主窗口里 `.global-container` 下面的东西都不上屏（看到的是桌面亚克力），视频层若放在 `#app` 里会跟着不可见。`.global-container` 在视频开启时 `z-index: 1`，保持 QQ 原生的 fixed 定位。

## 主窗口底层与查看器注入时机（.18）

主窗口里壁纸（图片或视频）在 `.global-container` 下面。QQ 在里面铺的整窗背景（多彩主题等）由 `renderer/backdrop.js` 按「是什么」找出：只看盖住窗口六成以上、铺了底色/背景图/背景模糊或是整窗媒体元素的那一层（含伪元素和不接收点击的元素），打 `data-liuli-cover`，`integration.css` 只清被标记的部分。不进消息列表、滚动区、输入框；对话框、遮罩、查看器和主题自己的玻璃层不碰。扫描挂在运行时的 layout 任务上，只沿着大盒子走，开销很小。

图片/视频查看器（路由含 viewer/player/preview/media/video）在窗口显示且 0.4 秒内尺寸不再变化后才注入（最多 2.5 秒，`load.js` 的 `settled()`），不和 QQ 按媒体尺寸调整窗口撞在一起。

查看器预置样式（.19）：主窗口在主题样式、壁纸或颜色变量变化后（防抖 1.5 秒、内容不变不重发）把「样式表全文 + 壁纸规则 + body 上的主题属性和 `--ll-*` 变量」经宿主桥交给 `load.js`（`viewerPreset`）。查看器路由时宿主先 `insertCSS` 这份内容并写入属性和变量，等窗口稳定后注入主题本体，再 `removeInsertedCSS`。

左栏玻璃画在 `.two-col-layout__aside::before`（z -1，不建立隔离），顶栏右边贴齐聊天区（`margin-right: 0; width: auto`），窗口按钮展开时操作区让开 `控件宽度 + 8px`。


## 内嵌页面、回到最新、输入框按钮折叠（.29）

- **频道页是 `<webview>`**：`.container-content > .guild-layout-wrapper.webview-wrapper > webview.guild-webview`。主窗口的样式进不去，`<webview>` 本身也在 `dom.js` 的受保护列表里，所以外壳不走 `mark()`，只打 `data-liuli-webview-pane`，玻璃画在外壳自己的 `::before` 上（`surfaces.css`），`backdrop.js` 不把它当整窗背景清掉（`SKIP` 含 webview）。内嵌页面里通过 `<webview>` 自己的 `executeJavaScript` 跑 `surfaces.js` 的 `guestTheme`：只改底色——页面大小的白/黑底变透明，较小的白块变淡卡片；按钮、头像、图片、视频、标签不碰。不读文字、不发请求、不碰协议。诊断 `webviewGuests` 只记主机名和计数。
- **回到最新消息**：`renderer/jump-bottom.js`，按钮挂在当前输入框（`.chat-input-area`）里、浮在右上角上方。只读写消息滚动容器的 `scrollTop`；远处先瞬移到离底部一屏，再平滑滚完；之后 1.2 秒内若行高变化没到底再补一次，用户滚轮/按键/按下即停止。设置项 `jumpBottom`。
- **输入框左侧按钮折叠**：`composer.js` 的 `stackBar()`。按正文行数分三档：一行横排；两行把最后一个图标挪到「+」上方（三角）；三行以上竖成一列。每个图标的位置是 `--liuli-pin-col/-row`，动画是 `left/bottom` 过渡。往回退一档之前先量一下：变窄后每一行是否还放得下，放不下就不退，所以不会来回跳。表情包正在「穿过」输入框时不改档。
- **表情包直接发送时不在输入框里露面**：落进输入框前给输入框打 `data-liuli-sticker-sending`，编辑区锁住当前高度、里面的图片不绘制；发出（编辑区清空）后的下一帧撤掉。若没发出去，最迟 2.6 秒撤掉，图片照常显示，不会留下一张看不见的草稿。
- **输入框里弹出的菜单**（截图 ⌄）：菜单到输入框之间的每一层强制 `opacity:1; filter:none` 等，任何一层带这些属性都会让菜单的背景模糊只模糊它自己。菜单里铺满整个菜单、自带底色（任何颜色）的包装层清掉底色（`menuLayers()`）。
- **卡片消息**：卡片里的小画布不再让整条消息被跳过（只有铺满一半以上的媒体才算图片消息）；纯白/纯黑的渐变底也算底板；底板透明度门槛 0.6。诊断 `cardMisses` 记录屏幕上仍有大块白底没被接管的消息结构（不含文字）。

## 菜单、链接、表情包面板（.30）

- **QQ 菜单的玻璃**：QQ 多彩主题给菜单的 `::before` 加了自己的底色和模糊，而且优先级比主题高。主题对所有 `.q-context-menu`、子菜单和 `⌄` 菜单内层用 `:not(#liuli-none)` 加 `!important` 强制自己的玻璃，菜单本身和 `::after` 不铺底色（`overlays.css`）。只改这几个元素的底色和模糊，不改位置。
- **链接**：`renderer/links.js` 拦截消息里链接的左键按下到点击（QQ 自己的处理不再执行），从 href / data-href / data-url / title / 文字本身取 http(s) 地址，经宿主的 `openExternal` 打开；取不到就交给 QQ。卡片消息（ark）仍由 `ark-external.js` 处理。主进程 `installLinkGuard` 包装 `shell.openExternal`：`c.pc.qq.com`、`c.mp.qq.com`、`urlsec.qq.com` 的中转页从 `pfurl/url/u/target/targeturl` 参数取出 http(s) 地址（最多拆三层）再打开，其他一律原样。设置项 `directLinks`。
- **表情包面板保持打开**：QQ 关面板是给 `.sticker-panel` 写行内 `display:none`。按下表情包时记下面板原来的 display，在 `data-liuli-keep-open` 期间用 `!important` 保持；指针移出面板（6px 余量）、Esc、窗口失焦、点面板外都会撤掉标记。撤掉之后面板回到 QQ 认为的关闭状态，不需要再调用 QQ。
- **卡片判断的重试**：`cards.js` 的 `classify` 遇到还没有尺寸的消息返回 `false`，这时不记入已处理，下一轮再判断。

## 画在画布上的卡片（.31）

QQ 9.9.36 的 ark 卡片（群公告等）是 `canvas.ark-view-message`。`cards.js` 的 `arkCanvas()` 把画布缩到 24×16 取样（`drawImage` + `getImageData`）：不透明像素里 55% 以上近白（或近黑）、彩色不超过 18% 的，打 `data-liuli-ark-glass="light"`（或 `dark`），CSS 用 SVG 滤镜 `#liuli-ark-light`：`feColorMatrix` 让透明度 = 1.5 ×（1 − RGB 平均），颜色不变，再用 `feComposite in SourceAlpha` 保留原来透明的角。深色同理（透明度 = 1.5 × RGB 平均）。读不到像素（画了网络图片）或带图片的标 `keep`，不加滤镜。还没画出来的画布最多再看 8 次（间隔递增）。键是「消息行 id + 画布尺寸」，变了就重判。滤镜定义在 `#liuli-ark-filters`（`liuli-owned-ui`）。

表情包面板的「按住」只被用户真实的点击（`isTrusted`）放掉，主题自己替 QQ 按发送键不算。

## .32 调整

- 画布卡片：`cards.js` 给外层气泡打 `data-liuli-ark-bubble`，`bubbles.css` 让它和同侧文字气泡用同一套底色、模糊（TG 布局下对方气泡有模糊）和 2px 内边距。滤镜系数 1.8。
- 表情包面板：不再强制显示 QQ 已隐藏的面板（QQ 连网格一起隐藏，强制显示只剩空壳）。按下表情包时在 `.expression-panel` 上挂 MutationObserver；QQ 隐藏 `.sticker-panel` 时，如果在按下后 2.5 秒内且指针还在面板上，就在同一个任务里点 QQ 自己的「表情」按钮重新打开（Vue 的更新在微任务里完成，绘制之前面板已经回来）。指针离开面板时，若面板是这样重开的，用同一按钮关掉（`bypass` 让主题自己的点击拦截放行）。

## 更新提醒、画布卡片的等待（.33）

- `renderer/update-prompt.js`：页面变化后（防抖 0.4 秒）查找标题叶子节点正好是「更新提醒」、同时有「下次启动更新」（或「稍后」「以后再说」）按钮的对话框。主窗口只在对话框类元素里找，其他窗口找整页。找到后替用户按「下次启动更新」，0.8 秒后还在：非主窗口调用宿主 `hideOwnWindow`（`load.js`，只隐藏调用者自己的窗口），主窗口给对话框和遮罩打 `data-liuli-dismissed`（`display:none`）。跟随设置项 `blockUpdate`。`auxiliary.css` 让小窗口里的按钮和输入控件都是 `-webkit-app-region: no-drag`。
- 画布卡片：没判断出来的放进等待集合，0.4 秒一轮、只看在屏幕上的，同一「行 + 尺寸」最多 40 次。遍历用快照（`[...set]`），否则放回去的元素会在同一轮里被反复访问。「图片卡片」要连续三次。卡片气泡两侧都用 `--ll-material-blur`。

## .34 调整

- 表情包连点：`chat-extras.js` 的 `holdBack` 是最先注册的捕获监听。发送进行中（`inflight`，从武装到输入框清空）再按表情包，按下、松开、点击都被拦下，按下的元素和图片地址进队列。发送完成后 `next()` 在同一个元素上重放 pointerdown → click（`replaying` 期间不拦）。重放必须在原来按下的元素上，QQ 的处理函数可能在图片上，不在外层格子上。
- 主题替用户按发送键只用 `click()`，不再派发 pointerdown/mousedown（会触发 QQ「点了面板外」的关闭）。面板关闭检测只观察 `.sticker-panel` 和它到 `.expression-panel` 的几层祖先的属性，不观察子树。
