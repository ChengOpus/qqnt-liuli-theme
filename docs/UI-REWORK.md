# 琉璃 UI 重构：部署、证据与验收

目标环境：Windows QQ 9.9.36-53644（64 位）、SnowLora 0.3.0+。本轮测试版本：`1.3.5+snowlora.9`。这是待实机验收的完整插件包，未宣称在目标 QQ 上全部通过。

## 本轮处理

录屏暴露的核心问题是多个模块同时管理同一块布局：CSS 悬停可以单独显示固定侧栏，JS 却没有同步预留空间；输入栏又依赖第一个编辑器节点和相对整个窗口的按钮坐标。缓存页面切换、鼠标事件节流及弹窗焦点变化会使这几套状态分离。

本轮删除旧 `liuli.css`、`layout.css`、`input-bar.css`、`no-dividers.css`，将仍需保留的规则归入独立职责文件；移除逐叶节点改色、虚拟行滑动、整页切换快照与重复消息观察器。维护约定见 [架构说明](ARCHITECTURE.md)。

| 区域         | 当前实现与限制                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左侧导航     | 使用真实布局列，200ms 展开／收起。运动期间裁切在自己的列内；取消 CSS 自行悬停展开的第二套状态。最终鼠标位置合并到下一帧处理，不丢弃离开事件。边缘触发区独立于动画中接近零的侧栏宽度。                                 |
| 顶部左右区域 | 左资料只给会话列让位，右窗口控件只给聊天列让位；关闭角短延迟，其余区域结合方向与停留判断。独立子窗口焦点与页面内子菜单保持所属区域展开。保留原生拖动／按钮命中区域。                                                  |
| 浮动输入栏   | 每次选取当前可见／获得焦点的原生编辑器，兼容缓存页面先于当前页面出现、同节点重新挂载及中间固定高度壳。输入栏浮在原消息视口上，真实高度驱动末尾留白；按钮定位在输入栏内部。                                            |
| 输入与附件   | 普通输入／删除只动画光标附近的短提示，不缩放或变换编辑器文字；中文组词期间不打断输入。原生图片／文件节点渐入；不重写内容，不延迟原生插入、删除、发送或文件操作。                                                      |
| 材质         | 统一低浓度底色、柔和高光、阴影与真实 `backdrop-filter`。保存的不透明度 `0.15` 对应基础玻璃 alpha `0.176`；搜索略提高底色以保证文字可读，保持单层磨砂。文字气泡模糊上限 12px，图片、视频、消息皮肤保留渲染路径。       |
| 搜索建议     | 保留底层原会话，不再用可见性规则隐藏列表。面板限制在会话列内，清除外定位壳与内滚动容器的重复材质、透明外沿。独立综合搜索采用单独作用域，原生数据、搜索、分类和跳转保持原逻辑。                                        |
| 资料与群管理 | 注册原生资料卡、独立资料路由，以及通过原生「发消息」按钮识别的资料卡变体。由一个外层拥有材质，内部结构底色清除；创建群聊不压暗整窗。真实 QQ 尚未核对的类名变体仍属待验收。                                            |
| 置顶         | 保留设置开关、横向分组线、图钉和可选淡底色；无数量与主题折叠控件，无悬停／选中左侧条。识别原生标题，即使它不在旧虚拟列表包装内。横线改用正文层级色，避免浅色主题色使其不可见。                                        |
| 图标与字体   | 输入代理按钮使用独立 SVG，不复制原生 mask／渐变 ID。资料在线状态使用可读图标色，邮箱等提示点用明暗适配的醒目语义色。移除消息与会话文字阴影、文本缩放动画及会话列表额外小数间距；不修改 Electron DPI 或 Windows 缩放。 |

布局的 200ms 过渡由 CSS 执行；尺寸观察器在该过渡中跳过纯宽度变化引起的重复整区测量，结束后再同步。输入栏真正增高时仍即时更新末尾留白。空闲没有常驻 rAF 或轮询。

## 配色与原配置

设置中的自定义调色盘支持 HSV、HEX、RGB、精确主题色，以及每个位置单独选色；不使用原生颜色弹窗。手动模式不会被壁纸取色覆盖。旧 Primary／Secondary／Tertiary 字段保留读取兼容，界面提供自定义色块。

六个预设来自 [Catppuccin 官方色板](https://github.com/catppuccin/palette) 的 Mocha（公开色板版本 1.8.0，MIT）：雾蓝 `#89b4fa`、长春花 `#b4befe`、薰衣草 `#cba6f7`、樱粉 `#f5c2e7`、杏桃 `#fab387`、鼠尾草 `#a6e3a1`。插件使用本地常量，打开调色盘无需联网。

- `liuli-dsh-settings`、壁纸、字体和布局设置不会清空；旧 `pinCollapsed` 值不再参与显示。
- `liuli-color-source` 保留自动／手动模式、HEX 和精确色设置。
- `liuli-color-roles` 保留旧角色字段，并在 `custom` 保存各区域 HEX。旧版忽略该对象，重新升级仍可读取。
- 本轮没有新增用户配置键或强制迁移；不清空 QQ 数据或 localStorage。

## 安装、版本核对与回退

1. 完全退出 QQ，备份当前 SnowLora 的 `assets/qqnt-liuli-theme` 目录和插件配置。
2. 在 SnowLora 插件管理中本地安装 `qqnt-liuli-theme-1.3.5+snowlora.9.zip`。手动替换时先移开旧主题目录，再解压完整新版，避免已删除的旧文件混入；`snowlora-plugin.json` 与 `load.js` 位于插件根部。
3. 重启 QQ，在 SnowLora 检查版本为 `1.3.5+snowlora.9`。设置 → 琉璃 → 诊断的资源清单应包含 `foundation.css`、`shell.css`、`composer.css`，不再包含旧 `layout.css`、`input-bar.css`。
4. 先测试缓存会话连续切换、侧栏反复进出、输入栏与搜索，再按下表验收其他页面。保留原设置即可观察变化，无需重置主题。
5. 回退时完全退出 QQ，恢复备份或安装 `.8` 完整 ZIP，重启并核对版本。不要清空 QQ 数据；升级新增的自定义颜色对象可由旧版忽略。

## 已执行的浏览器回归

两个测试均注入完整资源包与 renderer，运行匿名 QQ 结构 fixture；没有访问真实 QQ 账号、协议或数据库。截图及原始结果输出到被忽略的 `out/ui-qa/`。

`tests/ui-regression.cjs` 通过 1280×860／100%／浅色、1920×1080／125%／深色、900×680／150%／浅色组合，覆盖左右独立让位、浮动输入与末条消息可达、置顶开关、搜索单层材质、创建群聊透明遮罩、群资料内外层、独立资料路由、自定义颜色保存、Esc 以及真实滑块的 0px／18px 模糊变化。模糊对比截图的背景条纹由清晰变模糊。

`tests/runtime-lifecycle.cjs` 在 100%／125%／150% 各执行：

- 隐藏缓存页面排在前面仍选中当前输入框；连续切换 12 次，始终只有一个主题按钮层。
- 原编辑器移动到固定高度中间壳后仍浮动；原节点所有权属性被原生渲染清除后可恢复。
- 导航进出 4 次；展开过程逐帧检查实际列边界，点击邮箱后仍能收起。
- 页面内子菜单与模拟独立子窗口焦点保持父区域，关闭后恢复自动收起。
- 群成员搜索 28px 命中区；长昵称不覆盖身份标记，身份标签无底框。
- 原生置顶标题位于不同包装结构时仍有真实横线。
- 搜索外定位壳与内层无重复模糊；底层会话仍可见，面板不超出会话列。
- 未注册类名的群资料通过 UI 行为识别；受保护红包弹层不会成为材质目标。
- 工具面板磨砂在伪元素上，真实工具子菜单类名下的 520px／72px 固定位置不变；已移除旧硬编码偏移。原生隐藏工具仍保持隐藏，代理按钮调用当前原生事件。
- 输入、删除、中文组词与原生附件反馈；系统减少动画时不播放附件动画。
- 空闲调度队列为零，没有 renderer 未捕获异常。

这些比例是 Chromium 设备缩放，不能代替 Windows 系统缩放验收；模拟焦点事件也不能代替真实独立窗口联动。

运行方式：

```sh
npm install --no-save --package-lock=false playwright
CHROMIUM_PATH=/usr/bin/chromium node tests/ui-regression.cjs
CHROMIUM_PATH=/usr/bin/chromium node tests/runtime-lifecycle.cjs
# 可选：与另一个完整 checkout 的资源包比较
CHROMIUM_PATH=/usr/bin/chromium node tests/renderer-benchmark.cjs /path/to/baseline
```

## 性能对比的范围

`renderer-benchmark.cjs` 用同一个匿名 fixture 比较 `.8` 与 `.9`：每轮 12 次缓存切换、4 次侧栏进出、1 次顶部进出，分别运行三轮并交替先后顺序。记录 Chromium 的脚本、布局、样式和总任务时间，以及实际观察器数量、空闲回调、侧栏重叠和资源体积。原始数据仅保存在本地 `out/ui-qa/benchmark.json`。

本次最终运行的三轮中位数（Linux Chromium 156.0.8078.79，1280×860、100%，单位为整个操作序列的累计值）：

| 指标                             |          `.8` |          `.9` |
| -------------------------------- | ------------: | ------------: |
| 脚本执行时间                     |      47.76 ms |      74.61 ms |
| 布局时间                         |      72.59 ms |     114.78 ms |
| 样式计算时间                     |     243.36 ms |     185.98 ms |
| 总任务时间                       |     781.78 ms |     826.62 ms |
| CSS 资源                         | 282,007 bytes | 163,078 bytes |
| Renderer bundle                  | 479,199 bytes | 455,102 bytes |
| 同场景 MutationObserver 构造次数 |             5 |             4 |
| 同场景 ResizeObserver 构造次数   |             1 |             1 |
| 空闲 700ms 的 rAF 回调           |             0 |             0 |

观察器构造计数包含同一份浏览器测试工具；主题源码中保留一份页面变化观察器、一个尺寸观察器和两个局部属性观察器。两版该操作序列均未记录到 50ms 以上长任务。样式计算有所下降，但脚本和布局有所增加，总任务时间约增加 6%；这组基准没有证明整体性能改善。新版执行了原缓存切换修复和真实布局过渡，仍须在目标设备核对帧时间，不能只用资源缩小推导流畅度。

浏览器运行数据不能证明 Windows QQ 的 FPS、显存或实际 GPU 开销。真正的掉帧结论仍需要目标设备录屏或性能轨迹；本轮只报告已测数据和移除的重复工作。
