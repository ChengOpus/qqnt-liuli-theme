# 琉璃 UI 修复：部署、自查与验收

目标：Windows QQ 9.9.36-53644（64 位），SnowLora 0.3.0+。当前测试包 **1.3.5+snowlora.11**。这是本仓库开发分支的测试构建，不是作者官方版本；Windows QQ 实机验收尚未完成。

按用户要求，自己仓库的草稿 PR #1 已关闭，未合并；没有向作者 main 提交 PR。本轮只提交独立开发分支和完整测试 ZIP。

## 主动自查与兼容性

- 移除根据“发消息”文字推测资料卡的逻辑。仅使用注册的原生结构和独立资料路由，不把其他页面当卡片重写。
- 材质节点若被原生复用来展示红包／媒体，撤销主题自己的内联样式，保留之后的原生更新。
- 保留真实编辑器节点、选区、输入法、事件、消息与附件操作；没有重建原生搜索页面或模拟搜索数据。
- 不改 QQ.exe、SnowLora 加载器、QQ 协议或聊天数据库。`load.js` 是主题插件自身入口。
- 没有新增 renderer 观察器或轮询。页面观察与尺寸观察仍由一个调度器管理；移除按按钮文字搜索资料卡的额外扫描。
- 资料卡内部先集中读取图片背景排除条件，再统一清理结构底色，避免每处理一行就触发一次样式计算；已有静态定位标记不重复写入。
- Chromium 样式失效追踪定位到全局多选 `body:has(...[style])` 会把局部编辑器变化扩大到整页，已将判断归入当前输入区。隐藏缓存会话的多选状态不再干扰当前编辑器；原生转发、删除及退出多选仍保留。
- 继续核对作者的标题菜单层级约束，补齐标题弹层覆盖成员面板和悬浮输入区时的实际点击命中检查。
- `liuli-dsh-settings`、壁纸、字体、布局、自定义颜色均原样保留，无强制迁移。`pinGroup` 现在控制置顶短线与图钉，`pinColor` 控制可选淡底色；旧 `pinCollapsed` 不再参与显示。
- 手动主题色不会被壁纸覆盖；旧 Primary／Secondary／Tertiary 配置兼容读取，界面仍使用自定义 HSV／HEX／RGB 调色盘。六色预设来自 [Catppuccin 官方色板](https://github.com/catppuccin/palette)，本地使用，无联网取色。

## 安装、核对、回退

1. 完全退出 QQ，备份当前 SnowLora `assets/qqnt-liuli-theme` 目录及配置。
2. 在 SnowLora 插件管理中本地安装 `qqnt-liuli-theme-1.3.5+snowlora.11.zip`。手动替换时先移开旧主题目录，再解压完整包；不要把旧文件和新包混在一起。
3. 重启 QQ，在 SnowLora 检查版本 **1.3.5+snowlora.11**。无需重置设置。诊断资源中应有 `shell.css`、`composer.css`、`surfaces.css`，不再有旧 `layout.css`、`input-bar.css`。
4. 回退时完全退出 QQ，恢复备份或安装上一 `.10` 完整包；不清空 QQ 数据或 localStorage。

## 性能证据

使用相同匿名 fixture，Linux Chromium 1280×860，12 次缓存切换、4 次侧栏进出、1 次顶部进出，每版三轮、交替顺序。空闲无常驻 rAF，未增加 renderer 观察器。最终测量见本节下表；整个操作序列累计时间不是单帧耗时，不能据此宣称 Windows QQ 零掉帧或 GPU 已改善。

| 相同操作序列，三轮中位数          |  `.10` |  `.11` |
| --------------------------------- | -----: | -----: |
| 脚本 CPU（ms）                    |  58.56 |  61.37 |
| 布局 CPU（ms）                    |  91.25 |  94.22 |
| 样式计算 CPU（ms）                | 151.76 | 169.26 |
| 主线程任务 CPU 总计（ms）         | 627.00 | 655.18 |
| 空闲 700ms 的主题 rAF 次数        |      0 |      0 |
| 本场景侧栏覆盖会话列次数          |      0 |      0 |
| 观察器创建数（Mutation / Resize） |  4 / 1 |  4 / 1 |

初次基准发现新版累计主线程 CPU 高约 20%，继续用 Chromium 样式失效追踪定位到多选底栏的全局 `body:has(...[style])` 规则。将其收回当前编辑器后，最终相对旧包增量降至 **4.5%**；上表是修正后的完整三轮中位数，未选取最优单次。资料卡内部也改为批量读取、统一写入，避免逐行强制计算。

这仍不是整体性能验收通过，也没有把功能修复宣称为旧包之上的性能提升。最终三轮均未出现超过 50ms 的 Long Task；这不等于没有短帧丢失，也不测量真实 Electron GPU 合成。观察器计数来自整个测试页面，包含宿主桥的订阅，不能当成全局新增观察器数量。

## Windows QQ 尚未验收

- 实际 1920×1080／小窗口、100%／125%／150% 系统缩放、明暗模式与字体清晰度。
- 点击编辑器再滚动、多行输入、输入法、撤销、发送、文件图片操作、连续切换和独立聊天窗。
- 真实搜索建议、综合搜索空态／加载／结果／分类与跳转。
- 群资料全部窗口变体、群管理、工具角标、表情、右键子菜单和材质视觉一致性。
- 原生窗口关闭命中、Electron 拖动区域、父子窗口保持展开、侧栏连续操作。
- 登录、图片查看、消息转发、红包、小程序、语音视频和屏幕共享。
- 实际 CPU／GPU／FPS 与长时间稳定性；本包不标为全部成功。
