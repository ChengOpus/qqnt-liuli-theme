目标：Windows QQ 9.9.36-53644（64 位），SnowLora 0.3.0+。当前测试包 **1.3.5+snowlora.15**。这是本仓库开发分支的测试构建，不是作者官方版本。

**.15 同样没有在 Windows QQ 上跑过。** 不过从 .14 起，输入框和表情面板的处理用的是用户诊断包里的真实结构。 下面所有「通过」都指匿名浏览器夹具。夹具的结构来自作者源码和公开的同类主题里对真实 DOM 的记录，不是从真机抓取的；凡是结构拿不准的地方，代码里要么同时兼容几种写法，要么带运行时回退。真机上仍可能有偏差，偏差出现时请导出诊断（里面有不含文字的结构探针），按探针改，不要再猜。

## .15：表情/截图用 QQ 自己的图标、发送键、顶部阴影（2026-11-13）

依据：诊断包 `diagnostics-2026-11-13T13-58-44-433Z`（未提交）和三张截图。

- **表情 / 截图**：不再是主题自己画的两个按钮，而是把「+」菜单里 QQ 自己的「表情」「截图」两项原样移到「+」旁边（同一个节点，只改位置：`.liuli-pinned`）。图标、点击、截图右下角的小箭头和它的子菜单都是 QQ 自己的；展开「+」时它们留在原位，不会在菜单里再出现一次。在布局设置里置顶的其他项排在这两个后面。
- **表情图标的打开方式**：鼠标停在上面约 0.14 秒，或者点击，都打开表情面板并直接切到表情包页（默认「收藏」，之后记住你最后点过的表情包页；搜索页和 emoji 页不会被记成默认）。面板已经开着时再点不会把它关掉；emoji 只在面板里切过去。诊断里的面板结构是 `.sticker-panel__bar > .tabs-container > .tabs-container-item`，依次为搜索、emoji、收藏、GIF、各表情包，现在按这个结构找页签，不再靠位置猜。
- **表情面板只有一层玻璃**：外层 `.expression-panel-inner` 是玻璃，里面的 `.sticker-panel` 原来也被当成一个弹层又叠了一层，现在不再单独加材质。
- **发送键**：原来是一整块主题色实心按钮，箭头被 QQ 自己的文字层盖住了。现在是 30px 的浅色圆钮，箭头画在钮上；有内容可发送时换成很淡的主题色底、主题色箭头。QQ 自己的发送控件仍在原处、仍接收点击，只是不显示。
- **顶部阴影**：标题和操作区两块玻璃（以及窗口按钮胶囊）用的是和弹层一样的材质，里面带一道从右下角铺开的主题色晕染；这么矮的条上，它正好落在下沿，看起来就是一道阴影。顶部这一排现在改为均匀的玻璃加 1px 上沿高光，没有任何投影或晕染。
- 测试：夹具里的工具栏按 QQ 的结构带上截图箭头；`acceptance.cjs` 检查「+」旁只有 QQ 自己的两个图标（不是主题画的）、间距、展开时不重复、悬停打开收藏页、点击不关闭、发送键浅色且箭头可见。另加「顶部两块玻璃没有晕染、没有外投影」一项（用 .14 的样式跑这一项会失败）。旧的 `runtime-lifecycle.cjs`、`native-transitions.cjs` 改为点 QQ 自己的表情图标、检查移到「+」旁的截图箭头，并检查 QQ 再把某项藏起来时它不会被主题强行显示；`author-alignment.cjs` 的图标宽度改为和宫格里的图标比，夹具里常开的截图子菜单在收起宫格后手动移除（截图图标不再随宫格收起而隐藏）。输入动画的帧耗时对比改为两轮交替取较好的一轮（这台容器的单轮噪声会偶尔多出 2–4 个慢帧）。

## .14：按诊断包修正（2026-11-13）

依据：用户 35 秒录屏（`QQ20261113-214057.mp4`）和诊断包 `diagnostics-2026-11-13T13-41-56-563Z`（未提交）。

- **首次启动输入框盖住消息**：诊断里的真实结构是 `main.chat-msg-area`（overflow auto，不滚动）> `.ml-area.chat-msg-area__vlist`（overflow auto，不滚动）> `.q-scroll-view.ml-container.ml-root`（真正滚动）> `.virtual-scroll-area`（300000px）> `.ml-list`（sticky）。启动时消息还没渲染，主题找不到消息行，就把最外层的消息区当成了滚动容器并一直沿用，底部留白加错了地方：诊断里 `scroller: "region"`。现在没有消息行时先不决定，等消息出来再找离消息最近、真正溢出的那一层；之前选错的也会重新检查。测试夹具已改成这套真实嵌套，新增「首次启动」场景，用 .13 的代码跑这个场景能复现同样的状态（`scroller: "region"`、被盖住 50px）。
- **顶部灰带**：录屏里是标题和工具栏两块面板底下的投影，消息从后面滚过时看起来像一条灰带。顶部一排玻璃去掉了外投影，只留边缘高光。
- **表情 / 截图**：两个按钮都放在「+」旁边；鼠标悬停（或点击）表情按钮直接打开表情面板的收藏页，emoji 在面板里切换。去掉了单独的表情包按钮（它在真机上没打开面板：QQ 可能把关着的面板留在页面里只是变透明，主题把它当成已打开、就没去点）。点表情包直接发送的规则不变。
- **视频壁纸**：诊断显示主窗口里首帧图已经被撤掉（说明视频在播放），但屏幕上没有画面。QQ 主窗口是透明窗口，Chromium 在 Windows 上会把视频提升到硬件叠加层，透明窗口里这一层可能不显示。视频元素现在保持不透明度 0.999，不进入叠加层。这一条没法在这里验证；诊断包新增了视频层状态（是否播放、尺寸、该位置从上到下有哪些元素），下次导出就能看到。
- **禁止自动更新**：诊断日志里是 `update-guard … "D:\\QQ\\versions\\config.json", "action": "kept"`，即已经固定为 9.9.36-53644。
- 诊断包新增表情面板结构（打开面板时导出）。

## .13：性能、收发动画与追加功能（2026-11-13）

依据：用户 62 秒录屏（`QQ20261113-201458.mp4`，逐帧分析，未提交）和之后几条反馈。

### 性能

用 `tests/scroll-benchmark.cjs` 测：3000 条消息的虚拟列表，快速上下滑 120 次（约 3 秒、约 260 帧）；`MODE=switch` 是连续打开 12 次会话。数字是这一整段操作的主线程累计耗时（每种三轮取中位数，Linux 无 GPU 的 Chromium），不是单帧耗时。

| | 裸夹具（无主题） | .12 | .13 |
| --- | ---: | ---: | ---: |
| 快速滑动：主线程累计（ms） | 386 | 3996 | 1694 |
| 　其中样式计算（ms） | 24 | 2343 | 329 |
| 　慢帧（> 20ms） | — | 43 | 0 |
| 打开 12 次会话：主线程累计（ms） | 116 | 1322 | 915 |

折算下来：快速滑动时主题每帧约 6.5ms（.12 约 15ms），打开一次会话约 76ms（.12 约 110ms）。裸夹具几乎没有样式，真实 QQ 自己的开销比它大得多，所以「主题 / 裸夹具」的倍数不能直接套到真机上。

改了什么（按收益排序）：

1. **`:has()` 改为行属性**：样式计算 2343 → 426ms。原因见 [架构说明](ARCHITECTURE.md) 末节。
2. **新消息处理不再读几何**：原来每批新消息都取一次会话标题的位置，逼浏览器同步重排；吸底头像每帧对所有气泡取位置，现在只读跨底边的那一组。
3. **消息记录查找**：缓存未命中时原来要从整个 QQ 界面的组件树走起，在一个 4000 节点的模拟树里每条新消息要访问 8004 个节点，现在是 2 个。夹具里没有 Vue，这一项在上表里体现不出来，真机上收益应当最大。
4. **选择器分桶**：加载时展开 `X :is(.a, .b)`（逐元素比对 2412 个元素/伪元素，计算样式完全一致），并把 `[class*=new-msg]` 这类子串匹配改成具体类名。
5. **消息行不再跑弹层扫描**；主进程取不到自己 uid 时不再每批消息都请求一次。
6. **打开会话不再播放旧消息的入场动画**（TG 也是直接显示）。
7. **列表移动时气泡暂时不做毛玻璃**，停下后恢复。这一项减少的是 GPU 合成，上表测不到。

### 顶部「奇怪的加载」

录屏里鼠标移到工具栏下方时，标题栏正下方会出现一条横贯整个聊天区的灰色软阴影，移开又消失（逐帧差分是一整条横带）。来源是消息区顶部原生的装饰层（标题栏阴影、横幅底板一类），标题栏悬浮后它露了出来。这些层现在不绘制。具体是哪个节点在真机上没有确认；若仍出现，导出诊断包，结构探针会记录这些伪元素。

### 新消息收发动画（TG 式）

停在最新处时收到或发出消息：整列从输入框后面平滑上推（280ms），新气泡从头像一侧淡入放大。正在翻历史时不动画，也不移动视图。打开会话和加载历史消息不做任何动画。

### 追加的功能

- **群聊卡片**：点群名弹出的群资料小卡，是一个透明弹层壳里套一张白底卡，原来只有壳变了玻璃。现在弹层里大块的不透明白/黑底板和同色的行都会清掉，标签、按钮、头像、图片保留，按钮换主题色。
- **消息候选框**：输入时在输入框上方浮出的候选列表，类名不确定，按「浮动、够大、不透明无色底」识别，自动变成同一套玻璃。
- **顶部文件接收提示条**（「xx.gif 39 MB · 待下载 [下载][另存为][取消]」）：默认隐藏，按内容识别（只认传输按钮加大小/状态文字，不碰消息里的同名按钮）。设置 → 琉璃 → 布局里可以关掉。
- **表情包**：输入框左侧新增独立的表情包按钮，直接打开表情面板的收藏页（会记住你上次用的那一页）。输入框为空时点表情包立即发出；已经写了字时仍插入，不会把半句话发出去；小表情（emoji）始终插入文字。可以在设置里关掉。
- **禁止 QQ 自动更新**：默认开启，可在设置里关掉。原理：QQ NT 下次启动加载哪个版本由 `versions/config.json` 的 `curVersion` 决定；主题把它固定为当前运行的版本并设为只读，后台下载的新版本不会被加载（NixOS 的 QQ 包用的是同一个做法）。只改这一个文件；关掉开关只会把它恢复为可写。Windows 上这个文件的位置是从 QQ 实际运行的路径推出来的，没有在真机上确认过；找不到时什么都不改，诊断日志里会记一条 `update-guard`。

### 视频壁纸主界面不生效

三处原因一起修了：Windows 关掉「动画效果」时（系统报告减少动态效果）主题会直接停用视频壁纸；视频触发 `playing` 后就撤掉首帧图，但画面可能还没出来，结果一片空白——现在确认真的出了画面才撤；视频层会把 QQ 的主容器从固定定位改成相对定位，现在保持原生定位，只调层级，视频层改为铺满窗口。

### 新增和修改的测试

`acceptance.cjs` 新增：新消息动画（收到、发出、翻历史时不动）、群资料卡内层白底、未知类名的候选框、文件提示条（隐藏且不碰消息里的按钮）、表情包按钮与发送（含 emoji 和写了一半的情况）、视频壁纸（含减少动态效果）、诊断探针不含文字。`update-guard.cjs` 在临时目录里测固定、重复固定、释放和找不到配置文件四种情况。`scroll-benchmark.cjs` 是本轮的性能测量工具。

### 之后追加的要求

- **进入会话时最新消息被输入框挡住**：QQ 先滚到底，主题随后才加上输入框的留白，视图正好差一个输入框的高度。现在留白出现或变大时，如果视图本来在最新消息处就跟到底；已经往上翻的不动。
- **置顶会话**：短标记改成带光晕的渐变小条（悬停／选中时变长），整行加一层从左向右淡出的主题色，图钉换成小圆片。仍然只是行内样式，没有分组线、标题、数量、折叠。
- **玻璃质感**：背景模糊同时提高饱和度（1.35 → 1.8），壁纸本身的颜色能透出来；玻璃对角各加一点主题色和高光。所有玻璃面共用这一套。
- **顶部一排**：资料胶囊、聊天标题、聊天操作区、窗口按钮同高（36px）、同圆角、同一条起始线，内容垂直居中。
- **输入动画**：打字时发送键一侧泛起主题色的光，删除时是无色的同形光，图片／文件落入时更亮一些并淡入，拖文件悬停时有一圈描边；有内容时发送键点亮。
- **卡片类消息**（邮箱提醒、分享卡片、文件卡片）：新增 `cards.js`，按实际绘制结果识别不透明的白／黑底板、其上的黑灰文字和细分隔线，换成玻璃和主题文字色；带自己颜色的按钮、标签、图片不动。文件名换行后第二行不再右对齐；自己发的、没有气泡容器的卡片行与同组其它行对齐。

### 自查中另外发现并修掉的

- 伸手去点聊天操作按钮或搜索框时，指针进入顶部 36px 感应带，胶囊被唤出来盖住或顶走要点的东西。现在指针在这些控件上时，只有窗口最上沿 8px 唤出。
- 吸底的头像会滑到悬浮输入框后面。现在以输入框上沿为底。
- 页面里那个没有编辑器的空 `.chat-input-area`（作者源码有记录）不再被套上悬浮样式。
- 测试写死了本机不存在的浏览器路径时会一直挂起；`native-transitions.cjs` 现在也读 `CHROMIUM_PATH`。

### 没有改、需要知道的

- `load.js` 会在标题是「综合搜索」的窗口大于 1000×880 时把它缩到 920×740。这是之前加的，这次没有动；如果不是你要的，说一声就删。
- 文件图标上的深色下载圆标、聊天标题里显示成 `<$ÿ…>` 的群名片段：从截图看像是 QQ 原生状态，没有找到主题里会造成它们的规则，没有处理。

`acceptance.cjs` 在 1280×860／100%／浅色、1920×1080／125%／深色、900×680／150%／浅色三种条件下跑 `qq-native-fixture.html`，另有标题栏回退、会话打开时序、独立资料窗口（浅／深）几个单独场景。同一份测试在 .11 的代码上运行，七项全部有检查项失败（写这套测试的第一版时，每个条件三十多条），在 .12 上全部通过。

旧测试里有三处把错误行为写成了通过条件，已改：操作区 `margin-top` 必须是 36px（改为断言标题栏和消息视口不动）；独立窗口必须按路由名被标成资料卡（改为断言整窗材质存在）；删除时必须出现编辑标记（改为断言不出现）。

### 性能

同一操作序列（12 次缓存切换、4 次侧栏进出、1 次顶部进出），Linux 无 GPU 的 Chromium，每次调用内部三轮取中位数。主线程任务 CPU 总计（ms），共调用三次：

| 调用时的代码 | .11 | .12 |
| --- | ---: | ---: |
| 七项修复完成、追加视觉要求之前 | 597.43 | 573.61 |
| 加上全部视觉改动的第一版 | 609.37 | 662.33 |
| 把其中三处换成更省的写法之后（最终） | 652.18 | 658.12 |

.11 自己在三次调用之间就从 597 漂到 652，这台机器的调用间噪声大约 ±5%，所以这张表能支持的结论只有：最终代码和 .11 没有可分辨的差别（最后一次 +0.9%）。第二行那次 .12 明显偏高，据此改掉了三处：置顶短标记悬停时的高度过渡（每帧触发布局，改为直接切换）、两条覆盖全部气泡的 `:has()` 规则（改为脚本直接写标记）。脚本、布局、样式计算三项在最终一次分别是 61.69／92.74／171.55 → 63.94／88.15／173.28。

输入动画单独测：1920×1080／125% 下连续输入并删除 80 个字，统计耗时超过 20ms 的帧。最初的做法（整条输入栏的透明度渐变）每轮 7–10 个慢帧，动画关掉是 0 个；改成输入栏右端 180px 的非合成层重绘、发送键只切换颜色之后，三种分辨率下开和关都是 0–2 个，分不出差别。这是软件渲染下的数字，不能换算成 Windows QQ 的帧率。

## 主动自查与兼容性

- 移除根据“发消息”文字推测资料卡的逻辑。仅使用注册的原生结构和独立资料路由，不把其他页面当卡片重写。
- 材质节点若被原生复用来展示红包／媒体，撤销主题自己的内联样式，保留之后的原生更新。
- 保留真实编辑器节点、选区、输入法、事件、消息与附件操作；没有重建原生搜索页面或模拟搜索数据。
- 不改 QQ.exe、SnowLora 加载器、QQ 协议或聊天数据库。`load.js` 是主题插件自身入口。
- 没有新增 renderer 观察器或轮询。页面观察与尺寸观察仍由一个调度器管理；移除按按钮文字搜索资料卡的额外扫描。

- Chromium 样式失效追踪定位到全局多选 `body:has(...[style])` 会把局部编辑器变化扩大到整页，已将判断归入当前输入区。隐藏缓存会话的多选状态不再干扰当前编辑器；原生转发、删除及退出多选仍保留。
- 继续核对作者的标题菜单层级约束，补齐标题弹层覆盖成员面板和悬浮输入区时的实际点击命中检查。
- `liuli-dsh-settings`、壁纸、字体、布局、自定义颜色均原样保留，无强制迁移。`pinGroup` 现在控制置顶短线与图钉，`pinColor` 控制可选淡底色；旧 `pinCollapsed` 不再参与显示。
- 手动主题色不会被壁纸覆盖；旧 Primary／Secondary／Tertiary 配置兼容读取，界面仍使用自定义 HSV／HEX／RGB 调色盘。六色预设来自 [Catppuccin 官方色板](https://github.com/catppuccin/palette)，本地使用，无联网取色。

## 性能证据

使用相同匿名 fixture，Linux Chromium 1280×860，12 次缓存切换、4 次侧栏进出、1 次顶部进出，每版三轮、交替顺序。空闲无常驻 rAF，未增加 renderer 观察器。最终测量见本节下表；整个操作序列累计时间不是单帧耗时，不能据此宣称 Windows QQ 零掉帧或 GPU 已改善。

| 相同操作序列，三轮中位数          |  `.10` |  `.11` |
| --------------------------------- | -----: | -----: |
| 脚本 CPU（ms）                    |  58.56 |  61.37 |
| 布局 CPU（ms）                    |  91.25 |  94.22 |
| 样式计算 CPU（ms）                | 151.76 | 169.26 |
| 主线程任务 CPU 总计（ms）         | 627.00 | 655.18 |
| 空闲 700ms 的主题 rAF 次数        |      0 |      0 |
| 本场景侧栏覆盖会话列次数          |      0 |      0 |
| 观察器创建数（Mutation / Resize） |  4 / 1 |  4 / 1 |

初次基准发现新版累计主线程 CPU 高约 20%，继续用 Chromium 样式失效追踪定位到多选底栏的全局 `body:has(...[style])` 规则。将其收回当前编辑器后，最终相对旧包增量降至 **4.5%**；上表是修正后的完整三轮中位数，未选取最优单次。资料卡内部也改为批量读取、统一写入，避免逐行强制计算。

这仍不是整体性能验收通过，也没有把功能修复宣称为旧包之上的性能提升。最终三轮均未出现超过 50ms 的 Long Task；这不等于没有短帧丢失，也不测量真实 Electron GPU 合成。观察器计数来自整个测试页面，包含宿主桥的订阅，不能当成全局新增观察器数量。
